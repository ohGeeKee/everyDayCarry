PKI Certificates Rundown

	- A ////// B 
		- simple packet

	- how to ensure only B reads 
		- encrypt with B public key
		- only B can decrypt with private key

	- how to ensure message is unaltered
		- hash message and append to message encrypted with B public key 
		- decrypted message will match the hash of As plain texted trasmission

	- how to ensure sender nonrepudiation(signature) - along with aforementioned security provisions 
		- hash message, sign hash with A private key, append to message encrypted with B public key 
		- decrypted with As public key, the resulting hash matches that of As plain text transmission

	- how to ensure sender integrity(certificate)
		- register PKI with a certificate authority 
		- third party ensures signer identity and credential validity/revocation

	- how to ensure CA safe exchanges
		- utilizing common or CAs for A ////// B secure messaging

 				- information stored in a reverse lookup zone

				- email server

				- enables network clients to locate domain controllers and related services(kerberos, ldap, etc)

Active Directory Hierarchy

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	Typical uses & notes
	
	⁃	GPOs are linked to domains, OUs, or sites — OUs are commonly used to target GPOs to sets of users or computers

	⁃	Delegation: Use OUs to delegate administrative permissions without giving domain-level rights

	⁃	Trusts: Forests may contain multiple trees which implicitly trust each other inside the forest; cross-forest trusts can be created between different forests

	⁃	Global Catalog: Stores a partial replica of all objects for the forest to facilitate searches across domains

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	Namespace / DN examples

	⁃	DNS domain name: corp.contoso.com

	⁃	Lightweight Directory Access Protocol(LDAP) Distinguished Name (DN): CN=Alice,OU=Users,DC=corp,DC=contoso,DC=com

	⁃	UserPrincipalName (UPN): alice@corp.contoso.com (often used to sign in)

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	Key ideas (short)

	⁃	Forest: Top-level security boundary. Contains one or more trees. Example: contoso.com

	⁃	Tree: A contiguous namespace collection of domains that share a hierarchical DNS name (e.g., contoso.com and eng.contoso.com). Trees inside a forest share the Global Catalog and schema

	⁃	Domain: Administrative and replication boundary. Has a DNS name (e.g., corp.contoso.com)

	⁃	Organizational Unit (OU): Container used to group objects for delegation, GPO application, and organization (e.g., OU=Users)
		**generic containers(NOT TO BE CONFUSED WITH OUs): store system objects/parent objects of the created containers 
			- reject GPO application and other management differences from OUs 

	⁃	Objects: Users, Computers, Groups, Contacts, etc. Each object has attributes and a unique Distinguished Name (DN)

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

Quality of Service(QoS)
	
	- applies various treatments to different traffic

		ex. bandwidth: 20% voice•30% specific•50% other
		
	- delay
		- one-way: time required from source -> destination
		- two-way: time required from source -> destination + destination -> source 
		
	- jitter: variation in one-way delay between packets sent by the same application
		- jitter buffer provides fixed delay for packets, such as audio 

	- loss: purposefully discarding packets in the event queues get full

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
	
	- Audio Call Standards 
	
		- OWD: x =< 150 ms

		- Jitter: x =< 30ms

		- Loss x =< 1%

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	- Traffic Queuing

		- queued messages are forwarded in first-in-first-out(FIFO) method traditionally
		- tail dropped: new packets are discarded onced the queue is full 
			- TCP Global Sync: perpetual throttling and amplification cycle caused by excessive tail drops 
			ex. network congestion -> tail drops -> Global TCP Sync -> window decrease ->
				>network underutilization -> window increase -> network congestion…

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
		
	- Solution: Tail Dropping
		
		- random early detection(RED): purposely drops packs when traffic reaches a user defined threshold 
			- regulates the TCP window 

		- weighted random early detection: similiar to RED w/ granular packet controls defined by traffic classifications

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	- Classification/Marking 
		
		- traffic is organized into classes 
		- methods

			- ACL: similiar parameters as NAT usage 

			- Network Based Application Recognition(NBAR): deep packet inspection

			- Priority Code Point(PCP)/Class of Service(CoS)
				
				- ONLY OPERABLE over trunk or access + voice links
			
				- Layer 2 Classification(3 bits)

					- 0: best effort or “best effort…of whats left”
			
					- 1: background
	
					- 2: excellent effort 

					- 3: critical applications -> IP phones call signaling(PCP3)
		
					- 4: video

					- 5: voice data -> IP Phone(PCP5)
	
					- 6: Internetwork Control
	
					- 7: Network Control

			- Differentiated Services Code Point(DSCP)/Type of Service(ToS)

				- developed as a 3 bit extention to the IPP standard, a layer 3 equivalent to PCP 
				
				- Layer 3 Classification(6 bits)
				
					- 0: Default Forwarding(DF) -> best effort 

					- 46: Expedited Effort(EF) -> low loss/latency/jitter traffic(voice)
					
					- Assured Forwarding(AF) -> 12 values; 4 classes; 3 drop precedences 
						
						- syntax: AFXY -> X = class Y = drop precedence
						
						- Range: AF13 - AF41 -> [4] highest class [1] least likely to be dropped 
							ex. least to priority: AF13 -> AF12 -> AF11 -> AF21 -> AF31 -> AF41 
						
						- Binary: XY = _ _ _ || _ _  || 0 
							ex. AF11 = 001010 -> 0 0 1 || 0 1 || 0 -> 1 || 1 -> AF11
							**3 digits class - 2 digits drop precedence - last digit is always 0

					- Class Selector(CS) -> set of 8 standard values; backwards compatible with IPP
		
						- syntax: CS# -> # = 0-7
	
						- Range: CS0 - CS7 

						- Binary: # =  _ _ _ || 0 0 0
							ex. CS3 = 011000 -> 0 1 1 || 0 0 0 -> 0 1 1 -> CS3 
								**3 digits CS - last 3 digits are always 0 

					**DSCP representation(DSCP10, DSCP24, etc) are simply the decimal equivalent of the entire binary number 
						ex. AF11 -> 001010 -> DSCP10 
						ex. CS3 -> 011000 -> DSCP24 

				- DSCP Recommendations 
					
					- Voice Traffic: EF

					- Interactive Video: AF4x
					
					- Streaming Video: AF3x
					
					- High Priority Data: AF2x
							
					- Best Effort: DF

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	 - Queuing/Congestion
	
		- RED and WRED drop packets early to avoid tail drop
			- faster rate traffic is queued, and dropped once the queue is full

		- devices match traffic based on various factors(DSCP header) then queue
			
		- interfaces are limited to one frame at a time 
			- scheduler determines next frame 
			- traffic is scheduled based on priority 


		ingress -> routing,etc -> classification -> queuing -> scheduling -> transmission 


		- Schduler Methods
			
			- weighted round robin 
			
			- Class Based Weighted Fair Queuing(CBWFQ)
		
				- functions similiarly to weighted round robin with added bandwidth reservation
				- not ideal for voice data as it adds delay and jitter 


				congestion -> routing -> 10% classA -> queueA -> scheduler -> transmission 
							       15% classB -> queueB ->
							       15% classX -> queueX ->
							       60% classY -> queueY ->
				

					- schduler: YXBA…

			- Low Latency Queue(LLQ)

				- designates one or more queues as strict priority queues 
				- scheduler always takes next packet from priority queue until its empty 


				congestion -> routing -> 10% classA -> queueA 	          -> scheduler -> transmission 
							       15% classB -> strictPriorityQueue   ->
							       15% classX -> queueX 	          ->
							       60% classY -> queueY 	          ->
				

					- scheduler: BYXA… 
					- reduces delay and jitter of voice/video 
					- potentially starves other queues

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	- Shaping & Policing 

		- shaping: buffers traffic in the queue if configured rate is exceeded 
	
		- policing: drops traffic in the queue if configured rate is exceeded 
			- offers marking instead of dropping 
			- burst traffic: allows overages for a short period of time 
				- traffic is sent in bursts instead of a constant stream 


			SW1 -> CusR -> IspR ->Internet

				- customer pays for a 300mpbs package 
				- customer router [shapes] oubound traffic to 300mbps
				- ISP router [polices] traffic to 300mbps

FRHP(First Hop Resolution Protocol)

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++
++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	- 3 protocols
		
	- primary objective is load balancing and network redundancy 

	- configures 2 or more routers in an active & standby topology using virtual gateway and MAC addresses 

		- active/standby terms vary per FHRP protocol
	
	- routers send multicast “hellos” to negotiate roles 

	- end devices send ARP requests for the vMAC assigned to the VIP 

	- active router responds with the vMAC OR the backup router sends gratuitous ARP responses to update MAC address tables 

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	- HSRP: hot standby router protocol 

		- cisco proprietary 

		- active/standby election
		
		- single active - per - subnet load balancing 

		- v1/v2
		
			- v2 adds IPv6 support and increases the # of groups that can be configured
			
			- v1 & 2 are not compatible; configuration has to be consistent throughout the topology 
		
		- v1Multicast: 224.0.0.2
		
		- v2Multicast: 224.0.0.102 

		- v1MAC: 0000.0c07.ac##
				
			- ## = HSRP group

		- v2MAC: 0000.0c9f.f###
				
			- ### = HSRP group
	
	#int g0/0
	#standby [HSRP parameter]
	#standby version 2 
	#standby 1 ip 172.16.0.254
		- VIP
	#standby 1 priority 200
		- value•ip address determines active router 
	#standby 1 preempt
		- sets current router to active - when online - regardless of others in the topology 
	
	#show standby 
  

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++  
	
	- VRRP: virtual router redundancy protocol

		- open standard 

		- master/backup election 

		- single master - per - subnet load balancing 

		- Multicast: 224.0.0.18

		- vMAC: 0000.5e00.01##

			- ## = VRRP group 

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++  

	- GLBP: gateway load balancing protocol

		- cisco proprietary 

		- multi active - per - subnet load balancing 

			- AVG: active virtual gateway, elected for the subnet

			- AVF: active virtual forwarders, up to four gateways within a single subnet 
				**AVG can be an AVF 

		- Multicast: 224.0.0.102

		- vMAC: 0007.b400.[##][##]

			- ##: GLBP group

			- ##: AVF

STP

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++++

	- spanning-tree protocol 
		
		- anti broadcast-storming
	
		- configures a singular path amongst interconnected switches, without loops 
			
			**automatic functionality(one of the fundamental behaviors of cisco switches) 
					
		- places interfaces(trunking ports) in 1 of 2 primary states(there are 4 in total) 

			- forwarding: sending and receiving frames

			- blocking: receiving, but not sending BPDU messages in anticipation of a necessary state transition
				
				**listening & learning are transition states from blocking to forwarding 
				
				**this is the redundancy measure spanning-tree provides 
		
		- assigns interface roles 
				
			- root port: primary forwarding port(lowest cost toward the root bridge) 
			
			- designated port: forwarding 
			
			- non-designated port: blocking

MPLS(Multi Protocol Label Switching)

	- comparison to traditional switching(router function)
		- every router performs an IP lookup
		- traditionally, the router determines next-hop based on routing table
		- wasteful in terms of resources and time
	
	- MPLS uses LABLES instead, to improve QoS, connectivity, and mesh topology capabilities
		- packets are tagged with MPLS labels 
		- packets undergo “label-switching” as they travel through the internet, eliminating subsequent header examinations
			**edge routers are the only two that investigate the header for the necessary information(source, destination, transport layer data, QoS, etc) 
	
	- HOW IT WORKS
		- assign labels to each route in the routing table(16-######)
			ex. R1 - 1.1.1.1/32 == 100
				R2 - 2.2.2.2/32 == 200
		- share labels(LDP - label distribution protocol•automatic process)
		- build table-based forwarding table

Etherchannel
	
	- useful for load balancing between two devices(layers 2 & 3)

	- directs 2 or more ports to act as one in the interest of increasing bandwidth 
		**stp isolates frames/packets to a preferred route to avoid looping, rendering other links obsolete 

	- load is balanced based on flows
		**flows is the communication between two nodes(devices) in the network(consistent etherChannel path)

	- calculations are made to determine etherChannel path 
		- inputs for consideration
			- source MAC	
			- destination MAC
			- source and destination MAC
			- source IP
			- destination IP
			- source and destination IP
			- layer 4 port(tcp/udp)
	
	- interfaces(max of 8) must have identical configurations
		
	- methods of etherChannel
	
		- PAgP(Port Aggregation Protocol)
			**cisco proprietary, dynamic etherchannel negotiation 
		- LACP(Link Aggregation Control Protocol)
			**preferred, universal, dynamic etherchannel negotiation
		- Static etherChannel 
			**manual etherchannel formation not requiring algorithm or discovery protocol

Switch GK 

	- fundamental behaviors
		- learn
			- adds MAC address table entries
		- flood
			- sends frame out of all ports(multicast frames) ACCEPT receiving port
			**switch also floods when unicast frame is received from MAC address foreign to the table
		- forward	
			- forwards frame to port that responds with the destination Mac

	- interface(port) security
		
		- allowed on trunk/access ports
			**not allowed on dynamic auto/desirable ports

		- errdisable recovery
			- re-enables interfaces, after a specified time, if enabled for the listed 			  cause of disablement 

		- violation modes
			- shutdown
				- err-disabled state(shutdown) 
				- generates syslog and/or SNMP message 
				- violation counter + 1 
			- restrict 
				- discards traffic from unauthorized mack 
				- interface remains up
				- generates syslog and/or SNMP message
				- violation counter + 1 / per frame
			- protect 
				- discards traffic from unauthorized mack 
				- interface remains up
				- DOES NOT generate syslog and/or SNMP message 
				- DOES NOT increment the violation counter 	
		
		- MAC address aging
				- default: 0min (no age out) 
					- static addresses won’t age out 
					**sticky MACS don’t age out
					**#switchport port-security aging static 
						- enables aging for static addresses
				- type 
					- absolute
						- address is learned, aging timer starts, and is 						  removed once timer expires 
 					- inactivity
						- address is learned, aging timer starts, and 						  restarts upon every frame reception

Subnetting
	- subnet grid - - - - - - - - wildcard grid
		- /32 0 IPs - - - - - - - - 0 IPs
		- /31 2 IPs - - - - - - - - 1 IP
		- /30 4 IPs - - - - - - - - 3 IPs 
		- /29 8 IPs - - - - - - - - 7 IPs 
		- etc
	
	- subnet grid II - - - - - - - - wildcard grid 
		- /32 255.255.255.255 - - - - - - - - 0.0.0.0
		- /31 255.255.255.254 - - - - - - - - 0.0.0.1
		- /30 255.255.255.252 - - - - - - - - 0.0.0.3 
		- /29 255.255.255.248 - - - - - - - - 0.0.0.7 
		- /28 255.255.255.240 - - - - - - - - 0.0.0.15
		- /27 255.255.255.224 - - - - - - - - 0.0.0.31
		- /26 255.255.255.192 - - - - - - - - 0.0.0.63 
		- /25 255.255.255.128 - - - - - - - - 0.0.0.127
		- /24 255.255.255.0 - - - - - - - - 0.0.0.255 
		- etc
	
	- subnet concept I 
		- /0 contains 1 /0 network
		- /0 contains 2 /1 networks 
		- /0 contains 4 /2 networks 
		- /1 contains 1 /1 network
		- /1 contains 2 /2 networks 
		- /1 contains 4 /3 networks 
		- etc 
	
	- subnet concept II 
		- every network reserves 3 IPs(network ID - gateway - broadcast) regardless of structure 
		**/30(4 IPs :: 1 host) - acceptable configuration: point to point(router to router) usage of the gateway and host IPs 
	
	- subnet concept
		- /24: 11111111.11111111.11111111.00000000
			
			- 0s indicate host bits/changeable bits
			
			- octets with eight, 1s indicate the preservation of the IPs digits 
			
			ex. 192.168.1.0/24
				- 192.168.1.0
				- 192.168.1.1
				- 192.168.1.3 
				- etc
	
	- subnet concept
			
			- objective: divide *given network* into /24 networks
				*given subnet* -> A.B.C.D
				*/24 -> 255.255.255.0
				*/24 = 11111111.11111111.11111111.00000000

			- the last 1 indicates the interval of the network
				**count from 0, right to left 
				- interval = 256 IPs per network
			
			ex. 192.168.1.0/24
				- network: .0
				- gate: .1
				- broadcast: .255  
				- next network:  192.168.2.0/24 

	**subnetting rule 
	
			- boundary intervals are equal and always begin on .0
				**the math may check out according to vlsm, but essentially there are fixed ip address ranges		
			- 172.16.0.4/29 
				
				**gateway 172.16.0.10 is invalid 
				
				- /29 = 3 host 0s = 8
		
				- valid increments 172.16.0.0/29 + 8 -> 172.16.0.8 etc 
					**172.16.0.4 and 172.16.0.10 are located in separate subnets 
				
				**adjacent vlsm must adhere to increment boundaries 
					
					ex. [172.16.0.0/30](active) [172.16.0.4/30](unoccupied)

					      [172.16.0.0/29](occupied) [172.16.0.8/29](FIRST USABLE /29 BLOCK)
